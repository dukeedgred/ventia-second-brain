Schema Discrepancy: Asset Vision dbo vs SRAPC
Databricks validation extracts | June 2026

The difference is not labour tables. It is schema shape.

Asset Vision has the costing spine; SRAPC has richer job semantics but not raw costing tables inside transport_srapc.
AV Standard Asset Vision dbo

Already has the raw costing spine

The other Asset Vision schemas consistently include the generic job, resource, planned-resource, and timesheet tables.

38-40 Tables per source schema
84 Columns in job
24 Columns in timesheetitem
24 Columns in plannedresourceitem
  • timesheetitem carries Hours, Minutes, Quantity, Cost, ResourceType, and dates.
  • plannedresourceitem carries the same planned hours, quantity, cost, and resource fields.
  • The challenge is mapping generic Asset Vision rows into a clean contract/fault/activity view.
VS
OK transport_srapc

Richer job context, not raw costing tables

transport_srapc is a contract/reporting schema with SRAPC-specific job and attribute views.

42 Tables/views in transport_srapc
117k Rows in uvw_job
115k Rows in uvw_job_all_attributes
0 Raw timesheetitem / plannedresourceitem tables
  • Good SRAPC context: uvw_job, uvw_job_all_attributes, uvw_pbi_master_jobs_export, ArcGIS jobs.
  • Missing from this schema: exact raw jobasset, resource, timesheetitem, and plannedresourceitem.
  • Costing must bridge SRAPC job/fault semantics to all-contract costing tables in transport.
Correct costing path
transport_srapc.uvw_job* + transport.utbl_ref_job_costing_fault_map + transport.utbl_job_costing_timesheets_all_contracts
= clean unit cost

Speaker and source notes

Use this as the talk track: "The earlier assumption was too strong. The standard Asset Vision schemas already contain job, timesheet, planned-resource, and resource tables. The actual discrepancy is that transport_srapc is a richer SRAPC reporting schema, not a raw Asset Vision dbo schema."

Databricks-backed checks: source Asset Vision schemas such as ext_mssql_asset_vision_ven_gen7.dbo, ext_mssql_asset_vision_ven_rms.dbo, ext_mssql_asset_vision_vns_gen7.dbo, ext_mssql_asset_vision_vnz_gen7.dbo, and ext_mssql_asset_vision_vsm_gen7.dbo all include job, jobasset, timesheetitem, plannedresourceitem, resource, assetattribute, and formfield.

transport_srapc has 42 tables/views and includes uvw_job with 117,015 rows and uvw_job_all_attributes with 115,004 rows, but no raw jobasset, timesheetitem, plannedresourceitem, resource, or formfield table in that schema.

For pothole unit cost, the clean path is to identify SRAPC pothole jobs through SRAPC job/activity/fault fields, then join or reconcile to the all-contract costing spine: transport.utbl_job_costing_timesheets_all_contracts, transport.utbl_timesheetitem_jobs_allcontract, and transport.utbl_ref_job_costing_fault_map.
