How The Data Is Used

Operational reporting across assets, jobs, inspections, defects, lane access, traffic counts, capital works, timesheets, and inspection KPI dashboards.

Why This Score

Higher score because the documented schema covers the full operational chain: assets, inspections, defects, jobs, KPI views, lane access, traffic counts, capital works, documents, and timesheets.

Missing / limiting evidence: Still missing confirmed refresh ownership for some uploaded inputs, row-level data-quality profiling, and a defined set of golden reusable views for cross-contract comparison.

Evidence-Backed Strengths

  • Broad documented coverage across asset, job, inspection, defect, KPI, lane access, traffic, capital works, document, and timesheet domains.
  • `uvw_job`, `uvw_rm_jobs_reporting`, `vw_job_export_final`, and `uvw_job_geom` provide multiple work-order/reporting views.
  • `uvw_inspection_hazard_defect`, `uvw_inspection_kpi_1_dashboard`, and `uvw_job_kpi_2` show reporting-ready inspection and KPI structures.

Risks And Gaps

  • Several managed input tables are marked as created by the file upload UI, so refresh ownership and cadence need validation.
  • High breadth creates mapping work before WRU patterns can be reused across other contracts.
  • Production readiness is not certified by the table documentation alone.

Recommendations

  • Use WRU as a leading open-road candidate for reusable asset, job, inspection, and KPI mapping patterns.
  • Validate owners and refresh cadence for file-upload traffic, lane access, and reference inputs.
  • Define a small set of golden WRU views for asset, job, inspection, defect, and geometry before cross-contract reuse.

Scoring Rubric

Each dimension is scored from 1 to 5. A score of 5 requires broad, reusable, active, and well-evidenced data. No score claims production certification or row-level data quality.

25% weight Domain breadth

Breadth of documented domains such as asset, job, inspection, incident, KPI, finance, weather, traffic, capital works, and evidence.

25% weight Operational completeness

Evidence for the operational chain across assets, inspections, defects or incidents, jobs or work orders, completion, and supporting context.

20% weight Analytics sophistication

Documented KPI, reporting, Power BI export, weighted-score, pivoted, rolling, stripmap, or enriched analytical views.

15% weight Spatial readiness

Evidence for latitude/longitude, WKT, ArcGIS, road IDs, chainage, stripmaps, sections, or other geospatial/linear-referencing fields.

15% weight Reuse and governance readiness

Readiness for reuse based on view depth, source-boundary clarity, reference tables, non-temporary assets, and documented caveats.

Assumptions, Risks, And Gaps

These constraints are deliberately visible because unsupported maturity claims would be misleading.

Assessment Boundary

  • Scores use documented schemas, table names, column counts, domains, and selected stakeholder notes.
  • They do not use row counts, actual refresh telemetry, Power BI usage logs, or direct data-quality profiling.
  • Where a table is identified as created by file upload UI, that is treated as weaker governance evidence unless other source details exist.

Known Exclusions

  • Maximo source-table documentation is deferred from this pass at the user's request.
  • Shared enterprise or staging schemas are not contractor scores.
  • Asset Vision source catalogues are evidence for source context, but not scored as contractors.

Decision Use

  • Use high-scoring contracts as candidates for reusable data patterns.
  • Use low-scoring contracts to prioritise source discovery, ownership, and active-feed validation.
  • Do not treat any score as a certification that a schema is production-ready for enterprise asset master use.
